## Corporate Hub (PWA) — правила для разработки

### Цель проекта
Corporate Hub — корпоративное информационное PWA‑приложение для сотрудников (≈400 пользователей), которое снижает нагрузку на HR за счёт базы ответов на типовые вопросы и держит сотрудников в курсе новостей; доступ к приложению должен блокироваться при отключении сотрудника от корпоративной почты (авторизация через рабочий Outlook / Microsoft Entra ID планируется).

### Стек и версии
- **Платформа**: Web/PWA (Web App Manifest, Service Worker Cache API).
- **UI**: TailwindCSS через CDN `https://cdn.tailwindcss.com` (версия **динамическая**, зависит от CDN; для продакшена лучше закрепить).
- **Код**: Vanilla JavaScript (ES Modules) + шаблоны строк (без фреймворков и без сборщика).
- **Роутинг**: History API (`pushState`, `popstate`).
- **Auth**: заготовка под MSAL (`src/auth/msal.js`), детали tenant/app registration пока отсутствуют.
- **Локальный запуск**: любой статический сервер. Пример из `README.md`: `npx serve .` (рекомендуем **Node.js >= 18** только для локального сервера).

### Структура папок
- **`assets/`**: статические файлы на корне (иконка приложения и т.п.), используются напрямую из `index.html`/`manifest.webmanifest`.
- **`src/app/`**: вход приложения и инфраструктура SPA.
  - **`app.js`**: layout, рендер текущего маршрута, регистрация service worker, перехват кликов по ссылкам.
  - **`router.js`**: примитивная навигация (`navigate`) и подписка на изменения (`startRouter`).
  - **`routes.js`**: список маршрутов и функция сопоставления пути странице.
- **`src/pages/`**: страницы (по разделам продукта). Каждый `page.js` экспортирует функцию `...Page()` и возвращает объект вида `{ title, content }`.
- **`src/components/`**: переиспользуемые UI‑компоненты (пока пусто/заглушка).
- **`src/auth/`**: модуль авторизации (MSAL/Entra ID) и связанная логика.
- **`src/styles/`**: место под локальные стили/токены (если уйдём от CDN или понадобится кастом).
- **`src/assets/`**: ассеты, используемые из модулей `src/` (изображения/данные для страниц).

### Соглашения по коду
- **Именование**
  - **Файлы страниц**: `src/pages/<section>/<subsection>/page.js`.
  - **Экспорт страницы**: `camelCase` с суффиксом `Page`, например `homePage`, `vacanciesOfficePage`.
  - **Маршруты**: только **lowercase** и `kebab-case` в сегментах URL.
- **Форматирование**
  - **Отступы**: 2 пробела.
  - **Точки с запятой**: ставим (как в текущем коде).
  - **Кавычки**: двойные в JS (`"..."`) как в существующих файлах.
  - **Иммутабельность**: где возможно — `const`, функции без побочных эффектов для генерации `content`.
- **UI/верстка**
  - Не добавлять инлайн‑стили, предпочтительно Tailwind‑классы.
  - Контент страниц возвращать строкой, без прямого обращения к DOM вне `src/app/app.js` (исключение — интерактивные компоненты, тогда выносить в `src/components/`).

### Что нельзя делать / какие файлы не трогать
- **Не добавлять сборщик/фреймворк** (React/Vue/Angular/Vite/Webpack) без отдельного решения: проект задуман как статический PWA с ES‑модулями.
- **Не ломать офлайн‑поведение**:
  - любые изменения `service-worker.js` должны сопровождаться сменой `CACHE_NAME` (версионирование кэша),
  - не удалять из pre-cache критичные entry‑файлы приложения.
- **Не менять лицензию**: `LICENSE`.
- **Не коммитить секреты**: никакие tenant/client id, ключи, токены — только через безопасную конфигурацию (позже определим механизм).
- **Не редактировать `.gitignore` и структуру разделов** без явной причины: они фиксируют договорённости по репозиторию и продуктовой структуре.

### Первая задача для разработки
Сделать рабочую заготовку авторизации и блокировки доступа:
- **Реализовать `requireAuth()` в `src/auth/msal.js`** (инициализация MSAL, попытка silent login, обработка logout/expiry).
- **Подключить проверку в `src/app/app.js`**: до рендера страниц проверять статус, показывать экран «Вход / нет доступа», и **блокировать** UI при отключённой корпоративной учётке.
- **Добавить маршрут/экран** для состояния `not_configured` (пока нет Entra параметров) — чтобы приложение явно сообщало, что auth ещё не подключён.
